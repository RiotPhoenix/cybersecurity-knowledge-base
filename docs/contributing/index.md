# Contributing

Thank you for helping improve the knowledge base. Accuracy matters more than volume:
a smaller set of well-sourced, clearly labelled entries is more useful than a large set of
unverified ones.

## Ways to contribute

| Contribution | How |
|---|---|
| Propose a tool | Open a *New tool entry* issue on GitHub. |
| Report an error or outdated content | Open a *Content correction* issue, citing an official source. |
| Write or update an entry | Fork, branch, follow the [authoring standards](authoring-standards.md) and [template](tool-template.md), and open a pull request. |
| Add verification evidence | Describe what you tested, on which versions and platforms, in the pull request. |

## Workflow

1. Fork the repository and create a branch from `main`.
2. Make your changes following the [authoring standards](authoring-standards.md).
3. Run the [local validation checks](../getting-started/local-development.md#validate-before-opening-a-pull-request).
4. Open a pull request and complete the checklist.

## Rules that always apply

- Cite **official** sources for factual claims.
- Never include real credentials, private keys, internal hostnames, or private IP plans.
- Offensive tools require an authorisation notice and **lab-only** examples.
- Do not raise a [verification status](verification-statuses.md) without evidence.
- Do not include third-party logos, screenshots, or copied documentation unless their licence
  permits redistribution — link to them instead.
